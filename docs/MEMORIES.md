This document tracks important context, guidelines, behavioral rules, and technical learnings established during development.

## Tagged Guidelines and Learnings

- **[Code Quality & Standards]**: Do not blindly suppress `RuntimeWarning`s (e.g., division by zero or mean of empty slice) using `warnings.catch_warnings()`. Fix root causes natively using safe array masks (`np.where(mask, val, safe_val)`) or handling all-NaN slices explicitly.
- **[Code Quality & Standards]**: Generally preserve helpful code comments unless they are rendered outright incorrect by code modifications.
- **[Code Quality & Standards]**: Do not bundle dependency or lockfile changes (e.g., modifying `pyproject.toml` or regenerating `uv.lock`) into documentation-only updates to maintain strict separation of concerns.
- **[Dependencies & Environment]**: The project supports `numpy >= 2`; never bound `numpy < 2`. There are two locked environments: `uv.lock` (uv, `pyproject.toml`) and `pixi.lock` (pixi, `pixi.toml`).
- **[Dependencies & Environment]**: Minimum Python is 3.11. `pyproject.toml` and every PEP 723 header (in `src/eigenp_utils/` and `notebooks/`) must say `requires-python = ">=3.11"`; bump all of them together. The PEP 723 headers in `src/` are kept on purpose (modules are run standalone with `uv run`): each module with unconditional third-party imports lists them under their pyproject distribution names (only distributions pyproject declares; `try/except ImportError` imports may be omitted), enforced by `tests/test_package_metadata.py` (see `docs/AGENTS.md`). Extras: `[image-analysis]` includes tifffile, `[single-cell]` seaborn, `[fast]` numba; plotly is no longer a dependency. `uv.lock` / `pixi.lock` still list plotly and lack tifffile/seaborn/numba; they need regenerating with network access (the base `uv.lock` fails to parse: scikit-learn is not locked). Old dependency lines are tested on purpose by the `oldest-deps` CI job (3.11 with `pandas<3`, `numpy<2.3`, `scipy<1.16`, `scikit-image<0.26` as uv constraints), not as a side effect of an old Python. Raise those caps in a deliberate, separate change.
- **[Testing & CI]**: When testing local `src/` changes, set `PYTHONPATH=src` (e.g., `PYTHONPATH=src uv run --with '.[all,dev]' pytest tests/`) to guarantee local source files are imported instead of stale cached versions in `site-packages`.
- **[Testing & CI]**: Leave internal 3rd-party warnings (from anndata, scanpy, seaborn) as they are; do not suppress `UserWarning`s unless fixing an underlying implementation bug.
- **[Testing & CI / AnyWidget]**: Frontends for `AnyWidget` testing requiring DOM interactions or `Proxy` behaviors must use headless browser testing with `pytest-playwright` and a local `http.server` to host the `_esm` module.
- **[Deprecations]**: Every legacy name emits a `FutureWarning` "... will be removed in eigenp_utils 0.1.0" via `_conventions.warn_deprecated` (attributed to the caller; `tnia_plotting_3d` to the importing line); nothing is removed before 0.1.0. Viewers: `sxy`/`sz` (factories, `IsoScatterWidget`/`show_iso_scatter`), `x_s…z_t` (also `TNIAScatterWidget`), `colors=` (also `TNIASliceWidget`), `tnia_plotting_3d`. Plotting/I/O: `hist_imshow`, `numpy_to_stczyx_xarray`, `savefig_svg` without `fig=`. Intensity: `_my_clahe_`, `adjust_*_per_slice`, `test_z_axis_orientation` (now `check_z_axis_orientation`), `contrast_stretching(p_min=, p_max=)`, `normalize_image(lower_percentile=, upper_percentile=, dtype=)`, `contrast_stretch_per_slice(p_min_array=, p_max_array=, FLIP_Z_AXIS=)`. Geometry: `dask_extract_surface` (returns None), `best_focus_image(test=)`, `estimate_drift(return_ccm=)` and its default order `'xy'`, `apply_subpixel_drift_correction(drift=)`, `spacing=` (all four `image_and_labels_utils` functions), `calculate_spline_length(resolution=)`, `interpolation='bicubic'`. Single cell: `annotate_clusters_by_markers(beta=)`. The list is the `LEGACY` table in `tests/test_package_metadata.py`, which checks each warning; add new legacy names there. New code, tests and notebooks use the replacements (a test forbids the deprecated names in `notebooks/*.py`). Deprecated names stay importable but leave `__all__`.
- **[Conventions / `_conventions`]**: `src/eigenp_utils/_conventions.py` is the single source of the package conventions; it imports only numpy, the stdlib and (lazily) matplotlib, so it is WASM-safe; standalone modules load the sibling file when the package is not importable. Units (D01): µm everywhere, including `*_um` parameters; readers convert known length units (`to_um`: nm, µm spellings, mm, cm, m, Å; inch with a warning); `pixel`/`px` means uncalibrated; `resolve_pixel_sizes` is the one parser (a missing Z with known Y/X takes min(Y, X) with a warning; other missing axes: processing uses 1.0 with a warning, viewers 1.0 and a `px` scale bar). Scale-bar labels pick nm/µm/mm by magnitude (`format_length`); the data stay in µm. Display range (D02): `default_display_range`, computed on the source volume and shared by the static viewers, the widgets and `LabelAnnotator`. Processing percentiles (D27): (0.1, 99.9), the defaults of `_conventions.robust_range` (`clahe_u8` uses `robust_range`; `contrast_stretching` / `normalize_image` use `intensity_rescaling.PROCESSING_PERCENTILES`, which is defined there, not in `_conventions`). Colours (D03): `PALETTE` (white, lime, magenta, yellow, cyan, red, blue), `PALETTE_MINIMUM` for `'minimum'`, assigned by `default_colors` (skips colours already given); colormap names win over CSS names (`'gray'` is the colormap, end colour white). `per_channel` pads short lists with the default and raises for longer ones.
- **[Code Quality & Standards]**: Output policy (D07): library code never prints and never logs on the root logger: module loggers for information, `UserWarning` for anything actionable (`tests/test_package_metadata.py` enforces it; `task_calendar_scheduler.py` is exempt). `single_cell` / `bonsai_tree` `verbose=` reports are INFO logs, visible only once logging is configured. Functions that stopped printing carry a `Changed (D07` docstring note (tested).
- **[Image Processing & Spatial Geometry]**: xarray input (D31): `_conventions.check_zyx_input` rejects a DataArray with more than 3 dims with a TypeError naming `image_io.to_zyx`; it guards `windowed_slice_projection`, `voronoi_otsu_labeling`, `extract_surface(_tiled)`, `correct_z_intensity_decay`, `clahe_u8` and `best_focus_image` (`median_filter_fast` intentionally not). `to_zyx(da, S=0, T=0, C=...)` returns the (Z)YX data (NumPy stays NumPy, dask stays lazy) plus `get_stczyx_pixel_sizes` of the selection. NaN policy (R6-15): the median propagates NaN; `clahe_u8` maps NaN -> 0 with a warning; BaSiC raises; Z-decay skips all-NaN slices; the orientation check ignores NaN; the slab projections ignore NaN voxels (only all-NaN rays stay NaN). Seam tests across modules live in `tests/test_integration_seams.py`.
- **[Plotting & AnyWidget]**: In Matplotlib `violinplot` / `boxplot`, the `vert` parameter is deprecated; use `orientation='vertical'` or `orientation='horizontal'`. `orientation=` needs matplotlib >= 3.10, a minimum that `pyproject.toml` does not declare (matplotlib is unpinned).

If `channel_labels` is omitted, it defaults to string names or hex codes of assigned colormaps. The PNG label text is darkened (RGB x 0.75, `get_gui_channel_color`); the dark-theme GUI controls (row headers, histograms, scatter `channel_colors`) use `_gui_channel_color`, which mixes in white up to luma 0.45 and keeps the hue (the old `'#9e9e9e'` collapse of dark inks under `'minimum'` is gone). Labels and scale bar share one auto font size: 3% of the figure width, clipped to 8-24 pt (`_auto_fontsize_pt`). `figsize=None` is automatic from the physical extents (10-inch box for static views, 8-inch for widgets).

Each channel is normalised in its window (NaN/inf = no signal), gamma-corrected, then coloured: colormap names through their 8-bit LUT (`cmap(norm, bytes=True)[..., :3] / 255.0`, which handles background values without dark artifacts), plain colours as the exact ramp black -> colour (white -> colour for `'minimum'`); opacity scales a channel (fades it towards white for `'minimum'`); `'additive'` soft-clips highlights above 1.

- **[Image Processing & Spatial Geometry]**: Image volumes and coordinate points follow (Z, Y, X) dimension ordering. Functions like `windowed_slice_projection` default to `axis=0`.
- **[Image Processing & Spatial Geometry]**: Processing functions in `image_and_labels_utils` (e.g. `windowed_slice_projection`, `sample_intensity_around_points`, `optimized_entire_labels_touching_mask`) emit a `UserWarning` when `pixel_sizes` is `None` or misses an axis and fall back to 1.0. The ortho viewers fall back to 1.0 silently for `pixel_sizes=None` and draw a `px` scale bar; the bar is physical only when the X and Y sizes are given. Sizes are in µm.
- **[Image Processing & Spatial Geometry]**: The `adjust_gamma_per_slice` and `adjust_brightness_per_slice` functions are deprecated; use `correct_z_intensity_decay(method='gamma'|'gain', fit_model='exponential'|'linear')` (`method='exponential'` raises).
- **[Image Processing & Spatial Geometry]**: In `fit_basic_shading`, the darkfield is identifiable only from variation of per-sample baselines B_i (model I_i = B_i S + D). With a single image/volume (`s_s < 2`, e.g. one 3D volume with `is_3d=True`) `get_darkfield=True` warns once and fits the flatfield only (zero darkfield); the 'approximate' darkfield update is also skipped in iterations where no sample has B < 1. Previously this averaged empty sets: NaN residuals, "Mean of empty slice" every iteration, no ADMM convergence (60x256x256: 361 s, all-NaN output; now 2.8 s).
- **[Image Processing & Spatial Geometry]**: In `correct_z_intensity_decay` (D21) the per-slice p99 is fitted: `'exponential'` is bounded non-linear least squares (rate <= 0) seeded by OLS on log p99, `'linear'` exact OLS. Gamma is always anchored at t = 0.5, s = 2 * y_ref: `s * (I/s)**g_i`, `g_i = log(t)/log(t*y_fit_i/y_ref)`, clipped to [0.1, 10] (gain to [0.1, 100]); it depends only on ratios, so uint8/uint16/raw floats with the same counts agree. 8/16-bit ints saturate at the dtype max, 32/64-bit at the input data max. `exclude_background=True` leaves background-only and all-NaN slices out only in sparse stacks: the dimmest slice is the reference B (median, MAD), used only when the brightest slice's p25 is within 10 MAD of B and MAD > 0; a slice is background-only when p99 <= B + 10 MAD and p99 - B <= 5% of the top above B. Left-out slices take the fit interpolated between fitted neighbours, held constant beyond them (no extrapolation). `gain` with `fit_model=None` raises; brightening stacks warn and stay unchanged. The legacy `fit_model=None` ramp still depends on the dtype container (D21b open).
- **[Image Processing & Spatial Geometry]**: `fit_basic_shading(fitting_mode='ladmap')` starts with a tiny `mu`, so the first iterations shrink S to 0 and the update is ~0. As in BaSiCPy, stop only when the residual ratio <= `optimization_tol` AND the update ratio <= `optimization_tol_diff`, and keep B when ||S||^2 == 0. The ladmap darkfield is unreliable (R6-07 open: the dark offset is absorbed into S; `get_darkfield=True` with ladmap warns): use `fitting_mode='approximate'` for darkfield fits. The darkfield convergence term follows MATLAB BaSiC, not BaSiCPy (R6-17). NaN/inf input raises.
- **[Single Cell Analysis]**: In `score_celltypes`, evaluate cell type signatures using `scanpy`, `binned`, or `binned_weighted` methods, plus 'net' versions (`net_scanpy`, `net_binned`, `net_binned_weighted`) subtracting negative marker scores. Net binned scores are strictly clipped to `[0, 1]`.
- **[Single Cell Analysis]**: For `scanpy` clustering via `sc.tl.leiden`, specify `flavor='igraph'`, `n_iterations=2`, and `directed=False`.
- **[Statistics & Applied Math]**: In `stats.py`, `cohens_d` calculates exact Hedges' g correction factor using `scipy.special.gammaln`. `bootstrap_ci` uses BCa method with jackknife acceleration factor. `cohens_d` returns ±inf for constant groups with different means. The BCa jackknife leaves out rows (`axis=0`), matching the row-wise resampling. `remove_outliers` z-scores treat zero-variance columns as outlier-free (scipy's zscore gives NaN). `add_stat_annotations` reads the drawn group order from the axis tick labels when `order` is None (statannotations otherwise assumes first-appearance order).
- **[Statistics & Applied Math]**: Multivariate outlier detection in `remove_outliers(method='mahalanobis')` calculates Mahalanobis distance via pseudo-inverse covariance matrix (`np.linalg.pinv`). In sample-estimated covariance, squared Mahalanobis distance $D^2$ is bounded by $(N-1)^2/N$; thresholding uses exact scaled Beta distribution bounds ($D^2 \sim \frac{(N-1)^2}{N} \text{Beta}(\frac{d}{2}, \frac{N-d-1}{2})$) to prevent extreme outliers from masking themselves in small datasets, falling back to Chi-Square if $N \le d+1$.

Use `io.download_file_async` (pyfetch) in notebooks, since `download_file` raises in Pyodide. Download cells must return the path so marimo orders reads after them. marimo WASM batch-installs the PEP 723 header with micropip, so header entries without a WASM build (`git+` URLs, scanpy, pot) carry the marker `; sys_platform != 'emscripten'` (micropip skips them, uv still installs them natively). `single_cell` imports scanpy/anndata lazily via `_LazyModule`; never use `sc.`/`anndata.` at module level there. - **[Testing & CI / WASM]**: The `pyodide` CI job runs the whole `tests/` suite inside Pyodide, which cannot start processes (`subprocess.run` raises `OSError: [Errno 138] emscripten does not support processes`). - **[Documentation / Exclusions]**: Do not document or mention the Task Calendar Scheduler (`task_calendar_scheduler.py`) in any project documentation (e.g., README.md).
- **[Image Processing & Spatial Geometry]**: `_my_clahe_` is deprecated (FutureWarning via `warn_deprecated`) in favour of `clahe_u8`; its tests ignore only that warning via a targeted `filterwarnings` mark, and notebooks use `clahe_u8` (the CLAHE demo's reference is `skimage.exposure.equalize_adapthist`). `_my_clahe_` quantises the image to `nbins` levels before `_clahe`, so each gray level is its own histogram bin (no `bin_size`/LUT step); `tests/test_clahe_equalize_adapthist.py` checks agreement with `skimage.exposure.equalize_adapthist` (corr > 0.999).
- **[Image Processing & Spatial Geometry]**: `clahe_u8` is the fast N-D 8-bit CLAHE for segmentation (uint8 out; `surface_extraction` uses it for `clahe_clip > 0`). Backends: `numba` (`_clahe_numba.py`, imported lazily; used by `'auto'` when importable and ndim <= 3) and the NumPy fallback (Pyodide, no numba, ndim > 3); they are bit-identical (tested), so keep their arithmetic in lockstep: float32 leading-axis LUT blend, `np.rint` to int16, 7-bit fixed-point lerps `a + (((b - a) * w + 64) >> 7)`. OpenCV is not used (180 MB, 2D only); it serves only as a test oracle (`importorskip`), since the Y/X tiling, `x / k - 0.5` coordinates and single-pass clip (integer batch + strided residual, `clipLimit = 256 * clip_limit`) follow OpenCV and match `cv2.createCLAHE` to <= 2 levels. The leading axes (Z, ...) use pixel-centred tile coordinates (D20), so 2D output is bit-identical to OpenCV while 3D/N-D output changed; axis permutations into or out of the leading position differ by about 2 levels on average. `clip_limit=0` is the identity (unlike skimage/OpenCV); empty input returns an empty uint8 array; a trailing axis of length 3/4 warns (looks like colour). OpenCV's speed came from one fused pass (~2x) and threads (~4x); NumPy cannot thread it (`np.take` holds the GIL), so numba does both. The numba interp parallelises over slices, or over rows when Z < 2 * threads (2D/thin stacks). NumPy-path learnings: `np.take(mode='clip')` ~25% faster than 'raise'; per-tile uint8 `bincount` ~3x faster than one widened index; int16 lerps ~2.5x faster than float32. Non-uint8 input is mapped between `PROCESSING_PERCENTILES` (0.1, 99.9), via histogram + LUT for <= 16-bit integers.

Aux coordinates along C/T/Z (e.g. `color`, `role`) are kept on the mosaic.
- **[Image I/O]**: In `array_to_stczyx_xarray`, a dim relabelled to a different spatial letter loses its coordinate (a T axis in ms relabelled as Z would read as a Z pixel size); rebuilt coords keep a float coord's origin and direction (descending stays descending); integer coords with only stored `attrs['pixel_sizes']` get physical coords. Any uniform float coord counts as calibrated, so `coarsen().mean()` of an uncalibrated array fakes a pixel size.
- **[Image Processing & Spatial Geometry]**: `apply_basic_shading` computes `(I - D) / F - baseline + offset`. With `baseline` the result is zero-centred (about half the background negative), so the default output is float32; `offset='baseline_mean'` (or a number) shifts it back and makes the default output the input dtype (option chosen over clipping, int16 or rescaling). `return_offset=True` returns `(corrected, offset_value)` so the shift can be stored and subtracted. Integer casts warn when > 0.1% of pixels clip at either end: clipping zero-mean noise of std s at 0 biases its mean up by ~0.4 s, and dividing by F < 1 can overflow full-range data.
- **[Single-Cell / PaCMAP]**: `tl_pacmap(init=None)` uses PaCMAP's own `'pca'` init at any feature count (`'random'` only with `distance='precomputed'`) and warns, naming `'paga'`, an obsm layout and `'random'` as alternatives. The old "<= 100 features -> random" switch confused PaCMAP's `apply_pca` preprocessing threshold with initialisation. PaCMAP's PCA init on PC scores (`X_pca`) returns the leading PCs unchanged, so it is not PCA on PCA. PaCMAP standardises an ndarray init per axis (`StandardScaler`, x1e-4), so `init == use_rep` is routed to `'pca'` to keep the relative variance of the axes.
- **[Plotting & AnyWidget]**: `LabelAnnotator` (`label_annotator.py/.js/.css`) renders client-side, unlike the matplotlib-PNG ortho viewers: Python sends the current z-slice as 8-bit channels (`image_to_js`, header `uint32[4] (z, C, Y, X)`) and its labels (`labels_to_js`, header `uint32[3] (z, Y, X)` + `uint16`); the browser paints and returns the whole edited slice in `labels_from_js` after each stroke. Labels are stored as uint16; `labels`, `stack_labels` and `save` return/write uint32 (int32 with `signed=True`); ids > 65535 are rejected. `vmin`/`vmax` are `List(Float)` in data units (default `default_display_range`); a change re-quantises the slice to 8 bits in Python (float64, per-channel cache); the synced `data_range` trait is `[lo, hi, step, auto_lo, auto_hi]` per channel; JS slider drags are throttled to 100 ms with the final value on change, and pending values are dropped on a stack switch. Separate to/from traits avoid observer loops; `labels_from_js` is `traitlets.Any` (buffers can arrive as `memoryview`) and is reset to None after each message, because equal values are dropped. The z in the header (not the current `z` trait) decides which slice is written, so a message racing a slice change cannot land on the wrong slice; stack races are not guarded (R4-01 open: needs a stack id in the header). Every rendered view bumps `labels_resync`, and Python re-sends the slice only when `labels_to_js` is stale; views adopt `labels_from_js` sent by other views; z/stack keys are ignored during a stroke, and a slice reload mid-stroke cancels it. Unknown and computed-trait kwargs raise TypeError; trait kwargs are honoured and validated (opacity in [0, 1], tool, colour lists, no bool for vmin/vmax/gamma; `auto_increment=True` in semantic mode raises); `mode` and `background` are read-only after construction. - **[Single-Cell / Bonsai]**: `bonsai_tree` wraps Bonsai (github.com/dhdegroot/Bonsai-data-representation, CC BY-NC 4.0), a script repo, not a pip package: never vendor it; locate the clone via `bonsai_dir=` / `BONSAI_DIR` and run `bonsai/create_config_file.py` then `bonsai/bonsai_main.py` with `cwd` = clone root (both resolve relative paths against it, so pass absolute paths). - **[Single-Cell / Bonsai performance]**: Bonsai (single process) is deterministic: fixed seeds, byte-identical `edgeInfo.txt` across runs and BLAS thread counts in our tests. 76% of a 256-cell run is the next-nearest-neighbour reordering of `nnn_n_randomtrees` random trees, 20% greedy merging. `run_bonsai(n_threads=1)` (default) is 1.3-1.7x faster than multi-threaded BLAS with an identical tree (Bonsai's own `OPENBLAS_NUM_THREADS=1` is set after numpy import, so it does nothing). MPI (`n_procs`, `[bonsai-mpi]` = mpi4py + MPICH wheels, mpiexec looked up next to the interpreter) is 1.4x / 1.9x faster with 2 / 4 processes but changes the greedy merge order: a different tree of equal log-likelihood (±1 in 3500, distance Spearman 0.99), not reproducible across process counts.
